# Кэш ассетов в браузере

`public/client/asset-cache.js` сохраняет публичные файлы в Cache Storage
`microplanet-assets-v1`. Через него загружаются данные мира и озёр, GLB аватаров,
профессора и морских животных, включая встроенные в GLB текстуры.
Ресурсы загружаются по требованию; предварительного скачивания всех моделей нет.

## Поведение

- Для `/web/releases/<40-символьный SHA>/assets/…` сначала читается кэш.
  Новый релиз имеет другой URL и получает собственные данные. Разные query-параметры
  также дают разные ключи. Существующий HTTP-кэш сервера сохраняется.
- Для локальных URL без версии выполняется сетевой запрос с `cache: no-cache`:
  браузер проверяет актуальность HTTP-копии. При сетевой недоступности можно
  прочитать последнюю сохранённую копию. HTTP-ошибки не маскируются старым ответом.
- Одновременные запросы одного файла в странице объединяются. Каждый потребитель
  получает отдельное тело ответа, а каждая загрузка Babylon — отдельный контейнер
  сцены. Кэш хранит байты, а не разделяемые скелеты, анимации или GPU-объекты.
- Бюджет записи — 128 МиБ и 64 файла; старые записи вытесняются по FIFO, в том
  числе между релизами. Одновременные записи одной страницы сериализованы.
  Это не глобальная транзакционная квота между несколькими вкладками; браузер
  дополнительно применяет собственную квоту и может удалить хранилище.
- Слишком большой файл загружается без сохранения. Отказ Cache Storage или
  превышение квоты не препятствуют успешной сетевой загрузке.
- Не сохраняются ответы с кодом, отличным от 200, редиректы, HTML вместо ассета,
  ответы `private` и `no-store`. Доступ к API и авторизации остаётся на обычном
  `fetch`; глобальная функция `fetch` не подменяется. Публичные ассеты запрашиваются
  без cookies. Скрипты и стили используют существующее HTTP-кэширование.

Внешние файлы, на которые может ссылаться GLB, загружаются обычным механизмом
Babylon относительно исходного каталога модели. Кэширование их через этот модуль
не заявляется. Процедурные текстуры создаются в сцене, скачивать их не требуется.

Cache Storage доступен в безопасном контексте (HTTPS или localhost); если API
недоступен, приложение продолжает обычную загрузку. Кэш ассетов не делает весь
сайт доступным офлайн: HTML, код приложения, серверные функции и связь с другими
участниками имеют собственные требования к сети.

Для очистки только этого кэша в консоли браузера:

```javascript
await caches.delete('microplanet-assets-v1');
```

## Проверка

Из корня репозитория:

```sh
node --test services/soloapp_app/tests/*.test.mjs
```

Браузерная проверка поднимает временный сервер на loopback и отдельный профиль
Chrome. Она проверяет повторную загрузку после перезагрузки страницы, чтение
сохранённого ассета без сети, смену релиза, обновление локального файла, реальные
GLB с текстурами и запуск приложения. Нужны Chrome и Playwright; они не являются
новыми зависимостями приложения:

```sh
npm install --prefix /tmp/soloapp-browser-check --no-audit --no-fund playwright
SOLOAPP_PLAYWRIGHT_MODULE=/tmp/soloapp-browser-check/node_modules/playwright/index.mjs \
  node services/soloapp_app/tests/asset-cache.browser.mjs
```

При установленном Playwright в окружении можно не задавать путь модуля.
`SOLOAPP_BROWSER_CHANNEL` меняет канал браузера; по умолчанию используется `chrome`.

## Основания

- [MDN: Cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache) — постоянное
  хранение, явное управление версиями и ограничениями хранилища.
- [Babylon.js: загрузка моделей](https://doc.babylonjs.com/features/featuresDeepDive/importers/loadingFileTypes/)
  — загрузка контейнера и явное указание каталога относительных ресурсов.
