# Дверь между планетой и БЩУ

Около места появления на планете и у задней стены БЩУ находятся два представления одной автоматической раздвижной двери. При подходе створки открываются. Продолжите движение через проём: после подтверждения прохода участник оказывается с другой стороны, дверь закрывается. Точка появления отнесена от порога, чтобы исключить немедленный обратный переход.

Кнопка «К двери на планету» подводит к выходу внутри БЩУ; дальнейший переход выполняется через дверь. Комната физических процессов доступна после входа в БЩУ. Управление движением одинаково для клавиатуры, геймпада, сенсорного ввода и VR.

## Общее состояние

- `door_request` передаёт `requestId`, действие `open` или `pass`, исходную карту и известную ревизию.
- Сервер подставляет идентификаторы участника и пользователя из авторизованной сессии. Проверяются присутствие, исходная карта, ревизия и возможность прохода.
- `DoorAuthority` хранит состояние и квитанции в `planet_world.reactor.door`. Существующая блокировка строки PostgreSQL сериализует изменения от всех серверов; отдельная миграция схемы не нужна.
- `door_state` рассылается всем подключённым участникам, включая находящихся на планете. `door_ack` подтверждает конкретный запрос. Переход выполняется только по положительному подтверждению `pass`.
- После прохода начинается закрытие. Новое открытие запрещено в течение 500 мс, чтобы створки успели закрыться. Если никто не прошёл, дверь закрывается через 8 секунд по времени БД — даже без браузеров.
- Повтор запроса с тем же `requestId` возвращает сохранённую квитанцию, включая переподключение того же пользователя. Хранятся последние 512 квитанций; это ограниченное окно идемпотентности.
- Движение блокируется на пороге до подтверждения. Проверяется весь отрезок перемещения, поэтому большой шаг кадра не позволяет пройти через закрытую дверь.
- При потере связи сетевой клиент блокирует проход; в гостевом одиночном режиме используется локальная дверь. Старые серверы без `door_protocol: 1` не разрешают сетевой проход.

Синхронизируется логическое состояние двери; каждый клиент плавно анимирует створки за 0,5 секунды после получения состояния. Измерение близости и столкновение с проёмом выполняются клиентом. Сервер проверяет карту и порядок операций, но этот протокол не является серверной системой защиты от подмены координат.

Позиции участников теперь отправляются серверу и внутри учебных комнат, а не только на планете. Комнатные координаты не передаются симуляции рыб как координаты планеты.

## Сборка и проверки

ODB-файлы генерируются в каталоге сборки из актуального `world.hpp`. Использование сохранённых в исходниках старых bindings приводило к тому, что поле `reactor` не записывалось в PostgreSQL, хотя сервер отвечал подтверждением. Сквозной тест с двумя серверами проверяет именно сохранённое общее состояние.

Из корня репозитория:

```sh
node --test services/soloapp_app/tests/*.test.mjs
docker build --target build -f services/soloapp_app/deploy/Dockerfile -t soloapp-door-test .
```

Docker-сборка выполняет CTest, включая `door_test`: закрытый проход, конкурентные запросы, подтверждение после переподключения, проверка личности/карты, восстановление JSON и таймер без клиентов.

Для `tests/door-wire.mjs` нужны два **одноразовых локальных** сервера с общей тестовой PostgreSQL, применённой `deploy/schema.sql` и синтетическим auth-сервисом: токены из 64 одинаковых букв `a`, `b`, `c` соответствуют user ID из 32 таких букв. Оба сервера должны разрешать указанный тестовый Origin. Скрипт ограничен loopback-адресами; к рабочим учётным записям он не обращается. Модуль `ws` берётся из зависимостей `client-gateway` либо временного `NODE_PATH`.

```sh
DOOR_TEST_WS_A=ws://127.0.0.1:4188/api/v1/soloapp_app/v1/signal \
DOOR_TEST_WS_B=ws://127.0.0.1:4189/api/v1/soloapp_app/v1/signal \
DOOR_TEST_ORIGIN=http://127.0.0.1:4186 \
node services/soloapp_app/tests/door-wire.mjs
```

Браузерная проверка: открыть локальную страницу на `127.0.0.1` с `?door-audit=1` без авторизации. Она проводит игрока реальным кодом движения через обе двери, проверяет закрытие и отсутствие обратного перехода; результат выводится на странице. Временная шкала теста ускоряется согласованно с движением. `?reactor-test=1` остаётся отдельным локальным диагностическим входом напрямую в БЩУ.

Проверено 01.11.2026: 55 JavaScript-тестов, сборка C++ и три CTest; сквозной тест двух C++ серверов с PostgreSQL; семь проверок реальной Babylon-сцены. Физический VR-шлем не использовался.
