# Вопросы главному инженеру

Подойдите к главному инженеру у копировального аппарата (центр NPC: x=3.95,
y=0, z=7.5), войдите в аккаунт и включите микрофон voice chat. В радиусе 2.5 м
инженер слушает тот же микрофон, которым пользуется общий голосовой чат.
Произнесите вопрос и сделайте паузу примерно 0.8 с. Одна запись ограничена 8 с;
короткий шум менее 0.25 с не отправляется. Уход дальше 3.2 м, выключение
микрофона, выход из комнаты или скрытие вкладки отменяет текущий разговор.

Вопросы обрабатываются по одному. Одновременные начала речи согласуются между
участниками; действует возобновляемая заявка с таймаутом 8 с. Автоинструктаж и
реплики работников уступают разговору с инженером. Текст ответа виден рядом
с инженером. Настройка входящего звука voice chat управляет слышимостью ответа.

## Серверная цепочка

1. Авторизованный `POST /api/v1/soloapp_app/v1/engineer/respond` принимает WAV
   mono PCM16 16 kHz до 256044 байт. Используется та же проверка подписанной
   пользовательской идентичности, что у профессора снаружи.
2. Whisper распознаёт запись. Backend убирает из запроса разговорные вводные
   слова, сохраняя сокращения вроде СУЗ, ОЗР и АЗ-5.
3. Knowledge Search API получает `GET /search?q=…&mode=lexical&limit=100`.
   Его ранжирование основано на словах; морфологию обрабатывает сам сервис.
   Backend отбирает только `metadata.corpus=rbmk1000-vr-research` и
   `document_id`, начинающиеся с `rbmk1000:`. Корпус ВВЭР не смешивается с РБМК.
4. До трёх разных фрагментов, ограниченных по размеру, отправляются в
   [Ollama `/api/chat`](https://docs.ollama.com/api/chat) для краткого
   перефразирования на русском. Вопрос и источники передаются как данные;
   системная инструкция запрещает добавлять сведения вне найденных материалов.
   Ответ API сохраняет источники, страницы и ссылки.
5. При пустой выдаче Ollama не вызывается. Backend озвучивает точную фразу:
   **«Будьте серъёзнее или задавайте более осознанные вопросы»**.
   Ошибка поиска или модели возвращает 503, а не эту фразу. При отказе TTS
   остаётся текст и признак `audio_error`.
6. TTS на backend создаёт WAV. Браузер задавшего вопрос передаёт его отдельным
   аудиотреком по существующим WebRTC-соединениям voice chat. Микрофон не
   подменяется; ответ не попадает во вход распознавания. Звук доступен только
   участникам этой комнаты в радиусе 6.5 м. Удаление отключает слышимость,
   возвращение позволяет услышать оставшуюся часть ответа.

Транспорт использует браузер задавшего вопрос как ретранслятор серверного WAV,
а не серверного WebRTC-бота. При его уходе или разрыве соединения ответ
прерывается. Для соединений через разные NAT по-прежнему нужен рабочий TURN.
Человек без разрешённого браузером воспроизведения должен включить звук.

## Конфигурация

Backend читает `ENGINEER_SEARCH_URL`, `OLLAMA_URL`, `OLLAMA_MODEL`, а также
существующие `WHISPER_URL` и `TTS_URL`. Первые три обязательны для найденного
ответа; секреты в браузер не передаются. Суммарные таймауты зависимостей:
Whisper 90 с, поиск 5 с, Ollama 60 с, TTS 20 с. Gateway ждёт до 180 с.

Локальные восстановленные службы:

- Knowledge Search API: `http://127.0.0.1:8001`, проект
  `~/Documents/exps/vector-docs`, существующее `.venv`, модель из его кэша.
- PostgreSQL/pgvector: существующий контейнер `vector-docs-db` в Podman
  `ml-test-r1`, том `vector-docs-pgdata`, порт хоста 5433.
- Ollama: `http://127.0.0.1:11434`; модель выбирается через `OLLAMA_MODEL`.

Адрес `127.0.0.1` внутри pod указывает на сам pod. В локальном контуре добавьте
в игнорируемый `infra/local-macos/config.yaml`:

```yaml
engineer:
  search_url: http://192.168.5.2:8001
  ollama_url: http://192.168.5.2:11434
  ollama_model: qwen2.5:3b
```

`192.168.5.2` — пример host-loopback bridge Colima, его доступность нужно
проверить из вашего контура. Рендерер разрешает egress только на заданные
IP/порты. В production используются `whoami_config.engineer.search_url`,
`ollama_url`, `ollama_model` и явный список правил `egress`. Нельзя публиковать
неавторизованные API поиска и Ollama через публичный gateway.

## Проверки

- `node --test services/soloapp_app/tests/speech.test.mjs services/soloapp_app/tests/professor-voice.test.mjs`
- Штатная C++-сборка Dockerfile с `--target build` запускает CTest, включая
  изоляцию корпусов, атрибуцию, UTF-8, лимиты контекста и подготовку запроса.
- `tests/engineer_pipeline.py` запускает настоящий C++ HTTP-обработчик с
  временными Whisper/search/Ollama/TTS; проверяет пустой поиск, сбои и WAV.
  `--live-search --live-model` подключает восстановленные локальные службы.
- При статическом сервере `public/` на `127.0.0.1:4193` тест
  `tests/engineer-browser.cjs` проверяет два участника, реальный VAD,
  согласование ответа и отмену при уходе; HTTP-зависимости там заменены стендом.
- `tests/engineer-audio-browser.cjs` проверяет настоящее WebRTC-аудио в Chrome,
  отдельный трек, радиус слышимости, mute, возвращение и сохранение микрофона.

Генерация остаётся вероятностной: качество ответа нужно оценивать на вопросах
учебного сценария и сверять с источниками. Эти тесты проверяют интеграцию,
а не достоверность каждого возможного ответа модели или работу VR-гарнитуры.
