# Главный инженер и работники в БЩУ

Главный инженер (учёный из `scientist.glb`) стоит за пультами справа, рядом с копировальным аппаратом: координаты модели `(3.95, 0, 7.5)`, аппарата `(5.5, 0, 7.6)`. Это отдельный NPC, выбор аватара участника на него не влияет. Модель и её атрибуция уже входят в каталог аватаров.

Первый вошедший в учебную комнату запускает вводное занятие с задержкой 5 секунд. Источник — [QUICK_START.md](QUICK_START.md), перенесённый из исследовательского комплекта проекта. Читаются готовые реплики из цитат и таблиц, по предложениям. Указания ведущему, ссылки и примеры с незаполненными квадратными скобками не произносятся. Публикуемая копия лежит в `services/soloapp_app/public/assets/training/QUICK_START.md`; тест проверяет её равенство исходнику. При редактировании обновляйте обе копии.

## Поведение

- Текущая реплика и положение в тексте передаются участникам через надёжный WebRTC-канал комнаты. Ведущий клиент — участник с наименьшим сетевым ID. Поздний вход получает текущее место, а не отдельный инструктаж с начала. При выходе ведущего оставшиеся участники продолжают с сохранённого места. После опустевшей комнаты новое посещение запускает новый инструктаж.
- Когда участник начинает говорить в голосовом чате, учёный прерывается. После окончания речи и паузы он благодарит участника и напоминает структуру доклада, затем повторяет прерванное предложение. Реакция основана на активности голоса: она не распознаёт слова, не отвечает на содержание и не отправляет команды реактору. Текстовый чат отдельного Flutter-приложения не подключён.
- После принятой команды пульта учёный называет участника, орган управления и значение либо название действия; предлагает проверить фактический отклик. В серверном режиме источником служит подтверждённая запись команды. История при подключении, повторные записи и отклонённые команды не комментируются. Частые движения ползунка объединяются в комментарий о последнем значении.
- Учёный продолжает реагировать после завершения вводного текста. После ухода из учебной комнаты речь прекращается. В комнате физических процессов звук локально отключён; общая позиция инструктажа сохраняется.

## Звук и управление

Озвучка использует SpeechSynthesis браузера с языком `ru-RU` и предпочитает установленный локальный русский голос. Доступность и тембр зависят от браузера и ОС. Если воспроизведение заблокировано, нажмите «Включить голос инструктора». В VR ту же функцию выполняет выбор табло над учёным или кнопки на аппарате. Повторное нажатие отключает голоса главного инженера и работников для данного участника. Субтитры остаются на табло и в экранной панели. Короткому объявлению новой смены учёный уступает звуковой канал, затем повторяет текущую реплику. При отсутствии работающего синтезатора текст продолжается с расчётным временем чтения.

Для реакции на речь нужно включить существующий микрофон общего голосового чата. Инструктор заимствует его поток, вычисляет только уровень сигнала и передаёт признак активности. Он не запрашивает отдельный микрофон, не сохраняет аудио и не останавливает чужие дорожки. Для проверки диалога используйте гарнитуру: громкий звук из колонок может сработать как голосовая активность. У вкладок должен работать WebRTC-канал; при потере связи общий порядок реплик не гарантируется. Это клиентская синхронизация занятия, а не долговечное серверное хранение.

## Проверка

```sh
node --test services/soloapp_app/tests/instructor.test.mjs
node --test services/soloapp_app/tests/rbmk-model.test.mjs services/soloapp_app/tests/physical-system.test.mjs
node services/soloapp_app/tests/professor-voice.test.mjs
python3 -m http.server 4193 --bind 127.0.0.1 --directory services/soloapp_app/public
```

Откройте `http://127.0.0.1:4193/?reactor-test=1`: через 5 секунд появится первая реплика. Развернитесь к задней стене: учёный и аппарат находятся справа от места первоначального входа. Проверьте кнопку звука и субтитры, измените один орган управления, включите микрофон и произнесите доклад. Для проверки общей комнаты войдите двумя участниками на сервере: поздний вход не должен запускать текст заново, выход ведущего не должен сбрасывать позицию. Выход через портал останавливает местную озвучку. Отдельно проверьте взаимодействие лучом и доступность русского голоса в целевом VR-браузере.

Проверки реализации включают виртуальные часы, потерю сообщения об окончании речи, смену ведущего, объединение команд, отклонение некорректных сетевых снимков и неизменность публикуемого текста. Браузерная проверка двух вкладок использует настоящие обработчики `Network` с тестовым транспортом: прямое WebRTC-соединение в локальной среде не прошло ICE. События синтезатора заменяются тестовыми для воспроизводимости, детектор речи проверяется синтетическим потоком AudioContext. Это не проверка связи через TURN или слышимости звука в физическом шлеме.

Справка по используемым API: [SpeechSynthesis.speak](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/speak), [AnalyserNode.getFloatTimeDomainData](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData).

Повторяемая проверка браузерной интеграции (при уже запущенном сервере на 4193 и установленном Chrome):

```sh
npm install --prefix /tmp/soloapp-browser-check playwright
NODE_PATH=/tmp/soloapp-browser-check/node_modules node services/soloapp_app/tests/instructor-browser.cjs
```

## Работники

В комнате находятся ещё **7** NPC из той же модели, с надписями «Работник 1» — «Работник 7». Над учёным у копира указано «Главный инженер». Работники идут со скоростью 0,7 м/с по замкнутому проходу за пультами: `(-8, 5.3) → (-8, 9.1) → (8, 9.1) → (8, 5.3)` в координатах `(x, z)`, делая двухсекундную остановку на поворотах. Они разнесены по маршруту, обходят копир, инженера, стол журнала и портал. NPC не занимают места участников, не управляют пультами и не блокируют проход пользователя.

Все клиенты вычисляют положения по одной траектории и времени PostgreSQL из `reactor_state.serverTime`. Между снимками используется монотонный таймер браузера. Поздний вход и смена вычисляющего участника не начинают маршрут заново; сброс, пауза и скорость реактора на ходьбу не влияют. Лучший по задержке серверный образец защищает от рывков назад; остаётся погрешность доставки сети. Для одиночного локального просмотра до первого серверного снимка используется время устройства. При потере сети движение экстраполируется, после восстановления снова сверяется с сервером. WebRTC для синхронизации ходьбы не требуется.

При приближении на 1,7 м ближайший работник произносит **«Извините, сейчас я занят»** и показывает эту фразу над головой. Ответ слышит подошедший участник; другим пользователям он не транслируется. Для нового подхода нужно отойти дальше 2,5 м. Пауза между любыми ответами — минимум 6 секунд, между ответами одного работника — 30 секунд. Длительное стояние рядом не создаёт очередь реплик. В комнате физических процессов и скрытой вкладке работники не разговаривают.

Используется тот же браузерный русский голос и переключатель звука, что у главного инженера. Ответ работника временно прерывает локальное чтение, затем возобновляется текущее предложение общего инструктажа. Голосовой чат и объявление смены имеют приоритет. Если синтез речи недоступен, остаются субтитры; звук в целевом VR-браузере нужно проверять отдельно.

```sh
node --test services/soloapp_app/tests/workers.test.mjs
NODE_PATH=/tmp/soloapp-browser-check/node_modules node services/soloapp_app/tests/workers-browser.cjs
```

Браузерный тест проверяет семь загруженных моделей, подписи, обход мебели, синхронизацию двух вкладок с разными локальными часами через настоящие обработчики серверных сообщений, реакцию на приближение и приоритет озвучки. Серверные сообщения и синтез речи подставляются тестом; интеграционный `world_store_test.cpp` отдельно проверяет часы PostgreSQL между узлами и при смене ведущего.
